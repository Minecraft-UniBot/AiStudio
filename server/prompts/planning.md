# 第一阶段：需求规划

用户想创建一个 UniBot 扩展「{{name}}」（{{extension_id}}，类型：{{types}}）。

## 原始需求

{{user_request}}

## 你的任务：先问清楚，再规划

**不要直接开始写代码。** 第一阶段只做需求澄清与规划：

1. **先提问澄清**：如果需求中还有不清楚的地方（触发方式、参数、配置项、边界行为、
   是否需要复用已有扩展等），用 question 工具逐项向用户确认。至少覆盖：
   - 指令/API 的触发方式与大致行为
   - 是否已有类似扩展可复用（可先查看本地扩展市场 {{market_path}}）
   - 需要哪些可配置项（名称、含义、默认值）
   - 特殊边界与预期异常行为
2. **参考已有实现**：读取本地扩展市场注册表 `{{market_path}}`（只读），
   了解已发布的扩展，**优先复用已有扩展的能力**，避免重复造轮子。
   如果某能力已被市场扩展覆盖，向用户说明并建议复用，而不是重新实现。
3. **输出规划**：用户回答确认后，输出一份清晰的规划：
   - 功能清单（每个功能一句话）
   - 复用情况（复用/参考了市场中的哪些扩展）
   - 文件结构（需要创建哪些文件）
   - 配置项设计（名称、含义、默认值）
   - 测试计划（需要覆盖哪些场景）
4. **写入规划文件**：把以上规划写入草稿工作区的 `PLAN.md`（文件必须创建）。

## 约束

- 只能操作草稿工作区内的文件（{{allowlist}}）
- 市场注册表只读；禁止修改
- 规划阶段**不写实现代码**（`__init__.py` 中除脚手架外不做改动）
- 文档优先：扩展规范见本地文档（{{docs_path}}），禁止联网搜索本项目内容

## 0. 扩展系统架构（Agent 交接）

> 本章由原根目录 `AGENT.md`（扩展系统交接文档）合并而来，内容已按当前代码状态更新。

### 0.1 一句话概况

UniBot 扩展框架基于**装饰器声明模式**实现：扩展在文件顶部实例化唯一 `extension` 实例，
能力类用 `@extension.register_command` / `@extension.register_service` /
`@extension.register_renderer` 实例装饰器登记，Loader 统一实例化并提交。
测试全量以最新 `uv run pytest -q` 结果为准（2026-08 时点 224 passed）。

### 0.2 运行与验证

- Python 3.12，依赖由 `uv` 管理（venv：`UniBot/.venv`）
- 运行测试：`cd UniBot && uv run pytest -q`
- 静态检查：`uv run ruff check .`；可运行 `uv run ruff format`（docstring 双引号规范与格式化一致）
- 编译检查：`uv run python -m compileall -q Scripts Extensions`
- ⚠️ 不要用 `python -c "import Scripts.Extensions"` 直接导入：NoneBot 未初始化会报 `ValueError`，
  需走测试 conftest（`tests/conftest.py` 已 `nonebot.init()`）

### 0.3 扩展声明机制（核心）

旧实例方法 `register_services/register_commands/register_renderers` 与 `get_extension()` 工厂均已移除，
改为装饰器声明：

```python
from Scripts.Extensions import Command, Extension


# 唯一扩展实例放在文件顶部（imports 之后、类定义之前）
extension = Extension(config_model=WeatherConfig)


@extension.register_command
class WeatherCommand(Command):
    name = 'weather'
    description = '查询天气。'
    usage = '.weather [城市]'

    def declare(self) -> None:
        self.register_option('city', str, default='Shanghai', description='要查询的城市')

    async def handler(self, session: Uninfo, city: Match[str]) -> str | None:
        service = extension.api.get('weather')
        data = service.get_weather(city.result if city.available else None)
        return f'{data["city"]} 当前 {data["temperature"]}°C！'
```

关键设计点：

- 装饰器只在能力类上写标记属性（`_COMMAND_MARK` 等），不产生全局副作用；
  `Extension.__init_subclass__` 收集到实例私有 `commands` / `services` / `renderers` 列表
- ⚠️ 三个列表**必须实例私有**（`__init__` 里 `self.commands = []`）；定义成类属性会让所有
  `Extension()` 实例共享同一 list、能力互相污染（报「命令重复注册，冲突拒绝！」）
- 列表内存的是**类**（不是实例），由 Loader 的 `_commit_services` / `_commit_commands` /
  `_commit_renderers` 无参实例化并注册（命令按 `extension:<id>:<name>` 注册）
- 覆盖 = **类继承**：继承内置 `Command` 类覆写字段/方法，按同名 `command_id` 注册取代
- handler 返回式设计：`return` 字符串 / 图片 bytes / 消息片段，返回 `None` 表示不发送；
  图像模式由 `image_handler`（返回 `bytes`）承担，框架自动分发，handler 内禁止判断 `config.image.mode`
- 可选参数 `register_option(..., default=None)`：非 None default 会注入 Alconna（此时
  `Match.available` 恒 True，「始终可用」是合理语义）；`default=None` 不注入，`available`
  准确反映是否显式提供
- ⚠️ `Match` 对象无 `__bool__`：判断必须用 `city.available`，不能写 `if not city:`

### 0.4 两阶段绑定

- `Extension()` 构造 unbound 实例，只设 `config_model`；`metadata` / `config` / `data` / `api` /
  `logger` 默认 None。Loader 调内部 `_bind(metadata, config_store, data_store, api)` 一次性注入并置
  `_bound = True`；重复绑定抛 `ExtensionError`；扩展代码不能调 `_bind()`
- 绑定前访问受限：`config_value` 属性、`update_config()` 先 `_require_bound()`，
  未绑定抛 `ExtensionNotBoundError`；`get_config_schema()` 只读 `config_model`，unbound 也可用
- `id` 是 property：绑定后返回 `metadata.id`，未绑定返回 `_declared_id`；`__init__` 里
  **绝不能写 `self.id = ...`**（子类可能把 `id` 覆盖为只读 property → AttributeError），
  必须写 `self._declared_id`
- disabled / blocked 展示实例：`_register_display` 用 `Extension()` 建 unbound 实例，设
  metadata / state / failure_reason 后注册进 `extension_manager.registry`（不进
  `loader.extensions`，故 lifecycle 会跳过）；disabled 扩展不导入不绑定；依赖被阻塞的
  扩展标记 `blocked`

### 0.6 内置与用户扩展

- 内置扩展在 `Scripts/Extensions/Builtin/`（单文件）：`extension = Extension(id='List', name='在线玩家',
  version='1.0.0', types=('command',), builtin=True)` 构造 kwargs 传元数据，不继承
- 用户/市场扩展在顶层 `Extensions/`（目录式）：`Extension.toml` + `__init__.py` 入口模块
  （入口导出 `extension` 实例）；当前内置两个官方扩展：`Default`（默认模板 + 资源，
  无代码包）与 `Playwright`(渲染引擎)
- **类型可自由组合**（不再互斥）：代码能力（api/command/renderer）与无代码类型
  （template/resources）可混用在同一个扩展中。Loader 按「纯无代码 → 只提交静态注册；
  含代码能力 → 正常导入绑定，再追加 `_commit_no_code_package`」统一处理；混合扩展以
  registry 实例为展示主体（不写 no_code_info），模板配置仍走
  `renderer_manager.templates[id].config_store`；声明 renderer 必须提供 `[renderer] name`
  （校验条件已从 `types == {renderer}` 放宽为 `renderer in types`）
- 清单文件名 **`Extension.toml`**，常量收口在 `Scripts/Constants.py` 的 `MANIFEST_FILE`；
  兼容性校验统一走 `Base.validate_unibot_constraint`（Loader 与市场安装共用），
  对 `compatibility.unibot` 空或 `'*'` 直接通过，否则 `SpecifierSet` 校验
- Loader 跳过 `__pycache__` 与 `__init__.py`；`Config/Extensions.toml` 记录启停（缺失默认启用），
  启停读取唯一实现在 `Dependencies.load_enabled_config` / `is_extension_enabled`
  （Loader 内有实例缓存，`load()` 开头重置）
- 热重载安全：`ExtensionManager.load()` 开头自动调用 `reset()` 清空 registry / services /
  renderers / no_code_info / loader 发现状态；所有容器状态均为实例私有（构造器创建）

### 0.7 渲染架构

- 模板主题：Loader `_commit_renderers` 把 template 扩展的模板目录注册为模板注册表，
  `RendererManager._build_environment` 按「当前模板 → default → 首个可用」回退链构建
  Jinja2 环境；默认模板扩展为 `Extensions/Default/Templates/`
- 引擎：`Manager.start()` 在 `config.image.mode` 开启时 `renderer_manager.setup(config.image.renderer)`；
  图片模式关闭时 `_import_and_load` 跳过 render 类型扩展（disabled，reason「图片模式未开启」）
- Jinja2 环境 `enable_async=True`：模板渲染必须 `render_async()`；二次渲染
  `await environment.from_string(value).render_async(**vars)`（同步 `render()` 会产生未 await 协程警告）
- 配置注入：`_config_context`（async）预渲染含 `{{` 的字符串字段后再注入 `config`（深拷贝 +
  只读包装）；模板经 `config.xxx` 自读配置（如 `resolve_random(config.background)`）
- Jinja 全局函数：`random(dir)` 返回随机图片的**绝对路径**（模板自行包 `url()`）；
  `resource_path` / `resource_url`（同实现别名）/ `resource_text` / `resource_bytes` 访问资源扩展
- 并发安全：当前激活渲染器用 `contextvars.ContextVar` 承载（模块级 `_current_renderer`），
  并发渲染互不串扰；每引擎默认并发 = 1（`asyncio.Semaphore(1)`），超时默认 60s
- 渲染调用统一 `render_image(template, size, context=...)`；尺寸 `(width, height)`，高度 0 自适应；
  上下文数据需 `encode_context()` 转义

### 0.8 存储

- `ExtensionConfigStore(root_dir, model)`：配置文件 `Config/Extensions/<id>.toml`；
  `extension.config.value` 返回校验后模型，`update(values)` 校验 + 原子写盘 + 更新缓存
- 行为：**无字段模型不创建配置文件**（并 `unlink(missing_ok=True)` 清理遗留空文件）；
  有字段模型文件缺失/为空时**自动创建默认配置**（`_atomic_write` 的 `mkdir(parents=True)` 保证目录）
- `ExtensionDataStore`：内置扩展指向 `Path('Data')` 根目录，用户扩展 `Data/<id>/`；
  `read_json` / `write_json` 读写 JSON（Utf-8）
- `_atomic_write(file_path, content: str | bytes)`：新增调用点需注意签名

实现约定：

- **API 错误响应统一约定**（前后端共同遵守）：
  - 协议级错误用 HTTP 状态码 + `HTTPException`：401 未认证 / 403 权限不足 /
    404 REST 资源不存在（如 `/api/extensions/items/{id}`）/ 400 请求体非法
    （`Scripts/Api/Body.parse_json_object` 统一解析）
  - 业务结果一律 HTTP 200 + `{'code': 0|1, 'data': ..., 'message': ...}`；
    **禁止**在 HTTP 200 里返回 `code: 401/404/500` 等仿状态码字段
- **API 多语言**：面向用户的 message/detail 一律用 `Scripts.Api.Locale.text(key, **kwargs)`，
  禁止硬编码中文；语言按请求 Accept-Language 解析（`setup_request_language(app)` 中间件 +
  ContextVar，在 `webui_manager.mount()` 注册），未知语言回退中文。
  **与机器人消息语言（Config.toml 的 language / Messages 双语包）完全独立。**
  译文存放在 `Scripts/Api/Locales/{zh,en}.json`（按域嵌套，点路径键如
  `auth.token_expired`、`schema.config.<key>_label`），启动时载入内存；
  新增提示必须同时补 zh/en 两份，zh 值与历史中文逐字一致
- **配置表单 Schema 多语言**：`Api/Config/Schema.py` 的四个 `build_*_schema/groups()` 为构建函数
  （每次调用返回全新结构），label/description 经 `text()` 按请求语言生成；分组携带稳定 `id`
  （前端深链/选中态用 id 匹配，name 仅显示）。`Adapters.py` 的中文名称是数据源，
  展示译文由 Router `_localized_adapter` / Schema 平台选项注入
- **消息双语包**：机器人对外文案统一放 `Config/Messages.zh.toml` / `Messages.en.toml`
  （键结构一致；旧版单文件 `Messages.toml` 自动兼容为中文包），由 `Scripts/Messages.py` 按
  `config.language` 加载；WebUI「消息文本」编辑器读写当前语言的包文件。
  内置命令的 description/usage/参数描述、插件元数据等也在包内（导入时取值，改语言需重启或经
  PATCH /api/config 热重载：`_apply_language_change` 处理切换与回退）
- **消息隐藏区块**：`# Hidden Start` / `# Hidden End` 标记连同其之间的内容**完全不出现在** WebUI
  消息编辑器中（读路径 `strip_hidden_content` 整体剥离；写路径 `restore_hidden_content` 按
  「块前最近可见行」锚点原位回插，锚点丢失则带完整标记追加到文件末尾，提交文本中的标记与
  夹带内容一律丢弃）。机器人加载不受影响；实现在 `Scripts/Messages.py`，
  Manager 的 `read/write_messages_raw` 调用
- 静态路径（`/market`、`/renderers`、`/templates`）在参数路由 `/{extension_id}` 前注册；
  详情用 `/items/{id}` 避免扩展 id 吞掉静态路径
- 修改类接口 `Depends(require_role('admin'))`，列表/详情 `Depends(get_current_user)`
- 密钥字段（含 `key` / `secret` / `token`）只返回脱敏的「已配置」状态
- 引擎/模板切换写 `Config.toml` 的 `[image]` 段并 `reload_config()`；模板切换额外
  `renderer_manager.invalidate_all()` 使模板缓存失效
- 配置存储解析：registry 扩展用 `extension.config` / `update_config`；无代码 template 包用
  `renderer_manager.templates[id].config_store`（混合扩展两者并存，各管各的配置）（`ExtensionConfigStore.value` / `update`）
- 认证细节：bcrypt 校验经 `asyncio.to_thread`（登录失败对哑哈希校验抹平时延差，防用户名枚举）；
  已注销 refresh_token 存于 `Data/Users.json` 的 `revoked_tokens` 段（token → 过期时间戳，由
  data_manager 统一读写并惰性清理）
- WebSocket：cookie 名从 `Auth.COOKIE_ACCESS_KEY` 引用；access_token 解码走
  `Auth.decode_access_token_payload`
- Extension Studio 相关接口（`/studio*`）：启动用 `asyncio.create_subprocess_exec`，
  停止/读日志的阻塞调用包 `asyncio.to_thread`

### 0.11 生命周期与热重载

- `Scripts/Plugins/Extensions.py`（nb 插件）：导入时即执行 `extension_manager.load()` +
  `command_manager.build()`；Bot.py startup 钩子再 `await extension_manager.start()`，
  并按 `[hot_reload].enabled` 启动目录监听（`extension_manager.watcher.start()`）；
  shutdown 先 `watcher.stop()` 再 `extension_manager.shutdown()`
- `main()` 中 `nonebot.load_plugin('Scripts.Plugins.Extensions')`（在 `load_plugins` 之前，保证
  startup 钩子先注册先执行），**不写入** pyproject `[tool.nonebot].plugins`
- NoneBot lifespan：startup 按注册顺序执行，shutdown 按逆序——Bot.py 的 shutdown
  （data save）在插件 shutdown 之后注册，实际先释放扩展再落盘
- **热重载入口**：`.bot reload` 子命令 / WebUI POST `/api/extensions/reload` /
  watcher 自动触发；三者统一走 `extension_manager.reload()`（`_reload_lock` 串行化）
- **原子回滚**：reload 流程 = 语法预检（失败早退不破坏现场）→ `_snapshot` 快照全部
  注册容器 → 停用/注销/purge/load/build/start；任一环节异常则 `_restore` 恢复快照、
  复位旧扩展状态为 loaded 并重新 start，最后抛带 rolled back 说明的 RuntimeError
- **自动监听**：`Scripts/Extensions/Watcher.py` 轮询 `Loader.EXTENSIONS_DIR` 文件签名
  （mtime_ns+size，跳过 `__pycache__` 与隐藏项）；变更后经 debounce 静默期确认稳定才
  reload；失败已回滚故只刷签名防重复触发；开关/间隔运行时可改 Config.toml 热生效。
  ⚠️ 扫描必须动态读 `Loader.EXTENSIONS_DIR`（模块属性），不能顶层 import 绑定，
  否则测试 monkeypatch 不生效

- 循环导入约束：`Scripts/Extensions/__init__.py` 导入顺序

  Watcher 顶层只依赖 Config/Constants/Logging 与 `.Loader` 模块对象（动态读目录属性）；
  `Manager.py` / `Scripts/Api/Managers/WebUi.py` / `Scripts/Messages.py` 相关处使用函数内延迟导入（带注释）；
  `Base.py` / `Storage.py` / `Studio.py` / `Watcher.py` 顶部 `from __future__ import annotations`
- ⚠️ **插件加载前禁止普通导入插件托管包**：Bot.main() 在 `load_plugin('Scripts.Plugins.Extensions')`
  之前就会导入 `Scripts.Config` 与 `Scripts.Managers`，这条早期链上的任何模块若顶层导入
  `Scripts.Utils`（其顶层依赖 `nonebot_plugin_uninfo` / alconna）等插件托管包，
  uninfo 会抢先以普通模块进入 sys.modules，导致后续 `require()` 报
  「Module ... is not loaded as a plugin!」。需要此类工具时在函数内延迟导入并注释原因
  （先例：`Api/Managers/WebUi.py` 的 `safe_extract_zip`、`Bot.main()` 的 `Scripts.Api.Managers` 导入）。
- `Scripts/Constants.py` 只依赖标准库，任何模块都可安全导入；给 Constants 增加内容时
  禁止引入 Scripts 内部依赖，否则会形成导入环
- 测试隔离：`tests/conftest.py` 的 `_isolate_extension_manager` fixture 调用
  `extension_manager.reset()` 清空全部注册状态；monkeypatch 版本号用
  `Scripts.Extensions.Base.get_unibot_version`
- 编码规范见本文档第 1 节起；详细踩坑记录见仓库记忆 `/memories/repo/coding-rules.md`

- 管理器：一个文件一个 Manager 类，文件底部实例化单例；**可变容器状态必须在 `__init__`

- `Scripts/Managers/__init__.py` 统一导出常用管理器单例；WebUI 专属管理器（`data_manager` /
  `studio_manager` / `webui_manager`）位于 `Scripts/Api/Managers/`（其 `__init__.py` 同样统一导出）；
  个别模块因依赖方向特殊可绕过包聚合直接从模块导入。
- ⚠️ **`Scripts.Api` 必须等插件加载后再导入**：其 `__init__.py` 聚合全部路由，部分模块顶层依赖
  插件托管包（uninfo / alconna）；`Bot.main()` 中 `webui_manager.mount()` 前才导入
  `Scripts.Api.Managers`（函数内延迟导入）。
- 异步路由中的阻塞调用（bcrypt、zip 解压、子进程 wait、文件读写重 IO、psutil 采样）
  必须包 `asyncio.to_thread` 或改异步原语，禁止阻塞事件循环。
- 单文件超过 ~300 行即考虑拆分。

| 类型 | 规范 | 示例 |
|------|------|------|
| 文件名 | PascalCase | `Bot.py`、`Data.py`、`Server.py` |

## 3. 导入规范

导入分三组，组间空一行，组内按字母排序：

```python
# 1. 标准库
import asyncio
import tomllib
from pathlib import Path

# 2. 第三方库
import nonebot
from nonebot.log import logger
from nonebot_plugin_alconna import Command, Match
from nonebot_plugin_alconna.uniseg import Image, UniMessage

# 3. 本地模块
from Scripts.Config import config
from Scripts.Globals import render_template
from Scripts.Managers import cache_manager, server_manager
from Scripts.Utils import turn_message_text
from Scripts.Rules import command_group_rule
from Scripts.Extensions import command_manager, extension_manager
```

- 优先使用 `from X import Y`，避免 `import X` 后频繁 `X.Y`。
- 若有需导入相同目录下的模块，使用**相对导入**。
- **相对导入仅允许 `.`（同层）和 `..`（父级一层）**，禁止 `...` 及更深层相对导入。
- `Scripts/Extensions/` 包内同层模块互导用 `.module`（如 `from .Base import ...`）。
- 跨包或跨子目录引用一律用**绝对导入**，避免使用 `...` 或加深 `..` 层级。
  例如子目录 `Builtin/Commands/` 访问包根用 `from Scripts.Extensions import ...`，
  跨子目录用 `from Scripts.Extensions.Builtin.Services.PlayerService import ...`。
- 尽量少用 `..`：能用绝对导入表达的跨层引用优先用绝对导入（如
  `from Scripts.Extensions import ...`），仅在包内同层互导时使用 `.`。

## 4. 类型注解

- 使用 Python 3.10+ 联合类型语法：`str | None`，禁止 `Optional[str]`。
- 容器类型使用内置泛型：`dict[str, str]`、`list[str]`、`tuple[int, int]`。
- 只在类型不能由编辑器可靠推断、公共接口需要约束、Pydantic 模型字段或静态检查确有收益时添加类型注解。
- 局部变量、返回值显而易见的私有辅助函数、可由基类或赋值表达式推断的类型不重复标注。
- 不使用类型注解复述实现；复杂类型优先提取为有语义的类型别名。

```python
def get_player_name(name: str) -> str | None:
    ...

async def render_template(template_name: str, size: tuple[int, int], **kwargs) -> bytes:
    ...
```

## 5. 命令编写规范

**内置命令与用户扩展统一使用类式命令框架**：声明一个继承 `Command` 的命令类，
子命令用嵌套 `SubCommand` 类声明，由 `CommandManager.build()` 统一构建 matcher，
不要求作者拼接 Alconna DSL。

内置命令位于 `Scripts/Extensions/Builtin/`（一个文件一个命令，均以内置扩展
形式注册）；用户扩展在 `Extensions/` 下。

### 5.1 命令类声明

```python
from Scripts.Extensions import Command, SubCommand


class HelpCommand(Command):
    name = 'help'
    description = '查看所有可用命令的帮助信息。'
    usage = '.help [命令名称]'

    def declare(self):
        self.register_option('command', str, default=None, description='命令名称')

    async def handler(self, command: Match[str]) -> str | None:
        """文本分支：返回文本，由框架统一发送。"""
        return await turn_message_text(self.help_handler())

    async def image_handler(self, command: Match[str]) -> bytes | None:
        """图像分支：返回 PNG 字节，由框架在图像模式自动发送。"""
        commands = self.get_commands_list()
        return await render_template('Help', (600, 0), detail=None, commands=commands)
```

要点：

- **禁止在 `handler()` 内手动判断 `if config.image.mode:`**：需支持图片的命令覆写
  `image_handler`（返回 `bytes`），框架自动分发。
- **处理器通过 `return` 携带要发送的内容**（字符串 / 图片字节 / 片段列表 /
  异步迭代器），由框架统一 `matcher.finish()` 发送，处理器内无需接触 matcher。
- 返回 `None` 表示不发送（框架直接返回）。
- 需要逐行发送的内容使用异步生成器 + `turn_message_text()` 拼接为多行文本。也可以直接 yield 返回一行。
- 子命令使用嵌套 `SubCommand` 类声明，通过 `self.parent` 访问宿主命令实例。
- **定义顺序统一标准**：先完整定义主命令类，再依次定义子命令类（嵌套 `SubCommand`，
  每个子命令也先声明完整再定义其深层子命令）。子命令类不前置在父命令处理函数之前。
  类内方法顺序：**被 `@override` 覆写的方法（`declare()` / `handler()` /
  `image_handler()`，即框架要求实现/覆写的接口）统一放在最前面**，然后是类自身的
  私有处理函数，最后是嵌套子命令类。
- **处理函数归属统一标准**：每个命令的处理函数默认定义在**自己的类**内（如
  `remove` 子命令的解绑逻辑写在 `Remove` 类中）；仅当处理函数被**多个子命令公用**
  时才定义在父命令类下，并加分区注释（如 Bot 的 `_render_about` 被 `about` /
  `check` 共用）。子命令内不再通过 `self.parent.xxx` 调用父类的私有处理函数。
- 权限检查使用 `get_permission(session)`。
- 命令/子命令/参数名仅允许小写字母、数字、下划线。
- 可选参数（`required=False`）必须提供 `default`，否则校验失败；`register_option`
  等价于 `register_arg(..., required=False)`。
- 覆盖通过类继承实现：继承内置 `Command` 类，覆写字段/方法即可，未覆写的行为保留；
  覆盖命令按同名 `command_id` 注册取代内置定义（同一 `command_id` 重复注册会报错）。

### 5.2 扩展命令框架（Extension）

**内置命令与第三方扩展统一通过 `Command` / `SubCommand` 类注册声明式命令树**。

**惯例：扩展在文件开头实例化唯一 `extension` 实例，后续所有能力类都用
`@extension.register_xxx` 装饰器登记**（指令用 `@extension.register_command`、
服务用 `@extension.register_service`、渲染器用 `@extension.register_renderer`），
Loader 统一实例化并提交：

```python
from Scripts.Extensions import Command, Extension, SubCommand


# 唯一扩展实例放在开头
extension = Extension(config_model=None)


@extension.register_command
class WeatherCommand(Command):
    name = 'weather'
    description = '查询天气'
    usage = '.weather [城市]'
    
    @override
    def declare(self):
        self.register_option('city', str, default='SH')
        self.register_subcommand(Today())

    @override
    async def handler(self, city: Match[str]) -> str | None:
        return await turn_message_text(self.weather_handler(city.result))

    class Today(SubCommand):
        name = 'today'
        description = '今日天气'
        async def handler(self) -> str | None: ...
```

覆盖既有命令（继承内置命令类并覆写字段/方法，按同名 `command_id` 注册取代）：

```python
from Scripts.Extensions.Builtin.List import ListCommand
from . import extension
from typing import override

@extension.register_command
class MyListCommand(ListCommand):
    """只覆盖输出格式，数据获取逻辑继承不变"""
    description = '自定义列表（只显示在线）'
    usage = '.list'

    @override
    def list_handler(self, players): ...
```

**图像模式（image_handler）**：命令可覆写一个返回 `bytes` 的图像处理器，由框架在
`config.image.mode` 开启时自动分发并发送图片，无需在 `handler()` 内手动判断：

```python
class WeatherCommand(Command):
    name = 'weather'
    description = '查询天气'

    async def handler(self, session: Uninfo, city: Match[str]) -> str | None:
        return await turn_message_text(self.weather_handler(city.result))

    async def image_handler(self, session: Uninfo, city: Match[str]) -> bytes | None:
        return await render_template('Weather', (500, 0), city=city.result)
```

要点：

- `image_handler` 必须返回 `bytes`（图片字节）；框架收到后封装为
  `UniMessage(Image(raw=...))` 发送。
- 若图像处理器内无法生成图片（如权限不足、无数据），返回 `None`，
  框架检测到 `None` 即跳过图片发送，避免重复响应。
- `handler()` 只负责文本分支，不再包含 `if config.image.mode:` 判断；
  图像逻辑全部收敛到 `image_handler`，代码更清晰、职责单一。
- 子命令同样支持 `image_handler`（嵌套 `SubCommand` 内覆写）。

```python
# 文件底部实例化单例

```

```python
from .Cache import cache_manager
```

### 6.1 类与方法声明

- 类成员按「公开变量 → 私有变量 → 属性方法 → 私有方法 → 公开方法」的顺序定义；
  若按功能分组更清晰可以功能为准，但非必要不偏离该顺序。
- 类属性、实例属性、构造方法、公共方法、私有辅助方法按职责分组，相关方法相邻放置。
- 方法保持单一职责；方法名直接表达动作，不用注释补充含糊命名。
- 函数拆分粒度适中：除特殊函数外，单个函数主体保持约 6 行以上，避免拆得七零八碎。
- 优先使用实例方法；不访问实例状态时使用 `@staticmethod`，仅操作类级状态时使用 `@classmethod`。
- 覆写基类方法时使用 `@override`；只有确有抽象契约时才引入抽象方法。
- 参数较多时优先封装明确的数据模型，不用无语义的布尔参数堆叠调用。

## 7. 配置规范

- **TOML 文件读写统一使用 `tomlkit`**，禁止 `tomllib` 只读或手写字符串拼接。
  `tomlkit` 保留原文格式，用于需要回写（如 `Config.toml`、`pyproject.toml`、
  `Extension.toml`、`Driver.py` 依赖同步）的场景。
- 配置模型使用 Pydantic `BaseModel`，字段带默认值。
- 嵌套配置使用子模型（如 `ImageConfig`、`AiConfig`）。
- 配置校验使用 `@model_validator(mode='after')`。
- 用户可配置项放在 `Config.toml`，框架配置放在 `.env`。
- 新增配置字段必须提供合理默认值，确保向后兼容。

```python
class Config(BaseModel):
    port: int = 8000
    command_enabled: list[str] = []
    image: ImageConfig = ImageConfig()
```

## 8. 异步规范

- I/O 操作一律使用 `async/await`。
- 并发无依赖任务使用 `asyncio.gather()`：

```python
html_content, css_content = await asyncio.gather(
    template.render_async(**context),
    load_style(template_name, **context),
)
```

- 不关心结果的后台任务使用 `asyncio.create_task()`：

```python
asyncio.create_task(Target.group(group_id, scope).send(message))
```

- CPU 密集型或阻塞调用使用 `asyncio.to_thread()`：

```python
return await asyncio.to_thread(render, html_content, css_content)
```

## 9. 日志规范

使用 `Scripts.Logging.logger`（统一彩色控制台格式），按语义选择级别；需要打印完整异常堆栈时使用 `Scripts.Logging.exception_logger`：

| 级别 | 用途 | 示例 |
|------|------|------|
| `debug` | 模块加载、调试信息 | `logger.debug('Command {name} built.')` |
| `info` | 正常业务流程 | `logger.info(f'Player {player} joined server [{name}].')` |
| `warning` | 可恢复错误、异常 | `logger.warning(f'Request to {url} failed: {error}')` |
| `success` | 关键操作成功 | `logger.success('Data files loaded successfully.')` |
| `exception_logger.error` | 需要完整堆栈的意外异常 | `exception_logger.error(f'Failed to import extension {extension_id}: {error}')` |

- 日志消息使用英文，直接说明动作、对象和结果，不重复模块名、调用链或无用上下文。
- 正常完成日志不强制使用感叹号；避免“开始处理”“处理完毕”等成对流水日志，除非排查耗时确有需要。
- f-string 内嵌变量，不使用 `%` 或 `.format()`。
- 可恢复的已处理错误用 `logger.warning` 只记录定位信息；意外异常（命令处理失败、扩展导入/安装失败等）用 `exception_logger` 保留堆栈。

## 10. 错误处理

- 网络请求、文件操作等可能失败的代码必须 `try/except`。
- 捕获后记录日志并返回有意义的用户提示，禁止静默吞掉异常。

```python
try:
    response = await client.get(url)
    if response.status_code == 200:
        return response.json()
    logger.warning(f'请求 {url} 失败：错误的状态代码 {response.status_code}')
except Exception as error:
    logger.warning(f'请求 {url} 失败：{error}')
```

- 面向用户的错误信息应友好、明确，告知原因和建议操作。

## 14. 注释与文档字符串

- 使用 `"""` 双引号编写 docstring，内容为中文。
- **docstring 务必简洁明了、排版美观**：一句话能说清绝不用两句，不写废话与流水账；
  公共 API、非显而易见的约束和副作用使用一句话 docstring；名称与签名已能清楚表达用途时可省略。
- 行内注释只解释原因、约束或反直觉行为，不复述代码步骤。
- 注释保持简短；需要长篇背景时移入项目文档并在代码中保留简洁引用。
- docstring 结尾统一补中文标点（`。`/`！`/`？`）。
- 单行 docstring 保持内联：`"""内容。"""`；多行 docstring 定界符单独占行：`"""\n内容\n"""`。

```python
def get_permission(session) -> bool:
    """检查用户是否为超级用户或管理员。"""
    ...

def load_config(path: str) -> dict:
    """
    加载配置文件并合并到默认值上。
    """
    ...
```

## 17. 文件操作

- **所有文件操作统一使用 `pathlib.Path` 的方法**，禁止拼接字符串路径或使用 `open()` 裸调用。
- 优先使用 `Path.read_text()` / `Path.write_text()`、`Path.exists()`、`Path.iterdir()`、`Path.glob()`、`Path.mkdir()`、`Path.unlink()` 等方法。

```python
from pathlib import Path

config_path = Path('Config.toml')
if config_path.exists():
    content = config_path.read_text(encoding='Utf-8')
    config_path.write_text(content, encoding='Utf-8')
```

```python
# ✅ 正确：Path 方法
log_dir = Path('Logs')
log_dir.mkdir(parents=True, exist_ok=True)
latest = sorted(log_dir.glob('*.log'))[-1]

# ❌ 错误：字符串拼接 / 裸 open
log_dir = 'Logs'
os.makedirs(log_dir, exist_ok=True)
with open(f'{log_dir}/latest.log', 'r') as file:
    content = file.read()
```

## 18. 避免 else

- **尽量不使用 `else` 分支**，优先通过提前返回（early return）、守卫子句（guard clause）、`match` 等方式表达逻辑。
- 保持逻辑简洁明了，不重复无用的判断；能从既有条件推导出的分支不重复书写。
- `if/else` 一律改写为提前返回：

```python
# ✅ 正确：提前返回
def check_permission(role: str) -> bool:
    if role == 'admin':
        return True
    return False

# ❌ 错误：else 分支
def check_permission(role: str) -> bool:
    if role == 'admin':
        return True
    else:
        return False
```

- `elif` 可用于互斥的多分支条件判断。
- 仅当去掉 `else` 会引入重复计算、额外状态、错误的控制流或降低可读性时保留，例如 `try/except/else` 的成功分支。

## 19. 导入位置

- 导入默认全部放在文件顶部，并遵循标准库、第三方库、本地模块三组顺序；非必要不得将导入放在函数内。
- 仅在规避已确认的循环导入、延迟可选依赖、降低明确的启动成本时使用局部导入，并用一句简短注释说明原因。
- `TYPE_CHECKING` 导入用于纯类型依赖；不要为了隐藏普通导入而滥用。

## 20. 调用与排版

- 函数调用在不超过项目行宽时写在一行，避免每个参数机械换行。
- 单行长度避免过短或过长，尽量保持在 70-120 字符之间（Ruff 行宽上限 120）；超过行宽由 Ruff 统一格式化，
  不要手工对齐参数或使用反斜杠续行。
- 简短的函数签名、容器和返回表达式同样优先单行；复杂表达式先拆成有语义的局部变量。
- 在保持可读性的前提下可适当压缩代码：善用海象表达式 `:=` 合并赋值与判断、
  三元表达式 `a if cond else b` 简化单行分支，不为压缩牺牲可读性。
- 项目使用 Ruff 检查和修复：提交前运行 `uv run ruff check --fix .`。
- 可运行 `ruff format` 统一格式化：docstring 规范即双引号，与格式化结果一致无冲突。

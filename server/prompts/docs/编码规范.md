## 0. 扩展系统架构（Agent 交接）

> 本章由原根目录 `AGENT.md`（扩展系统交接文档）合并而来，内容已按当前代码状态更新。

### 0.1 一句话概况

UniBot 扩展框架基于**装饰器声明模式**实现：扩展在文件顶部实例化唯一 `extension` 实例，
能力类用 `@extension.register_command` / `@extension.register_service` /
`@extension.register_renderer` 实例装饰器登记，Loader 统一实例化并提交。
当前全量 **126 项测试全部通过**。

### 0.2 运行与验证

- Python 3.12，依赖由 `uv` 管理（venv：`UniBot/.venv`）
- 运行测试：`cd UniBot && uv run pytest -q`
- 静态检查：`uv run ruff check .`；可运行 `uv run ruff format`（docstring 双引号规范与格式化一致）
- 编译检查：`uv run python -m compileall -q Scripts Extensions`
- ⚠️ 不要用 `python -c "import Scripts.Extensions"` 直接导入：NoneBot 未初始化会报 `ValueError`，
  需走测试 conftest（`tests/conftest.py` 已 `nonebot.init()`）

### 0.3 扩展声明机制（核心）

旧实例方法 `register_services/register_commands/register_renderers` 与 `get_extension()` 工厂均已移除，
改为装饰器声明：

```python
from Scripts.Extensions import Command, Extension


# 唯一扩展实例放在文件顶部（imports 之后、类定义之前）
extension = Extension(config_model=WeatherConfig)


@extension.register_command
class WeatherCommand(Command):
    name = 'weather'
    description = '查询天气。'
    usage = '.weather [城市]'

    def declare(self) -> None:
        self.register_option('city', str, default='Shanghai', description='要查询的城市')

    async def handler(self, session: Uninfo, city: Match[str]) -> str | None:
        service = extension.api.get('weather')
        data = service.get_weather(city.result if city.available else None)
        return f'{data["city"]} 当前 {data["temperature"]}°C！'
```

关键设计点：

- 装饰器只在能力类上写标记属性（`_COMMAND_MARK` 等），不产生全局副作用；
  `Extension.__init_subclass__` 收集到实例私有 `commands` / `services` / `renderers` 列表
- ⚠️ 三个列表**必须实例私有**（`__init__` 里 `self.commands = []`）；定义成类属性会让所有
  `Extension()` 实例共享同一 list、能力互相污染（报「命令重复注册，冲突拒绝！」）
- 列表内存的是**类**（不是实例），由 Loader 的 `_commit_services` / `_commit_commands` /
  `_commit_renderers` 无参实例化并注册（命令按 `extension:<id>:<name>` 注册）
- 覆盖 = **类继承**：继承内置 `Command` 类覆写字段/方法，按同名 `command_id` 注册取代
- handler 返回式设计：`return` 字符串 / 图片 bytes / 消息片段，返回 `None` 表示不发送；
  图像模式由 `image_handler`（返回 `bytes`）承担，框架自动分发，handler 内禁止判断 `config.image.mode`
- 可选参数 `register_option(..., default=None)`：非 None default 会注入 Alconna（此时
  `Match.available` 恒 True，「始终可用」是合理语义）；`default=None` 不注入，`available`
  准确反映是否显式提供
- ⚠️ `Match` 对象无 `__bool__`：判断必须用 `city.available`，不能写 `if not city:`

### 0.4 两阶段绑定

- `Extension()` 构造 unbound 实例，只设 `config_model`；`metadata` / `config` / `data` / `api` /
  `logger` 默认 None。Loader 调内部 `_bind(metadata, config_store, data_store, api)` 一次性注入并置
  `_bound = True`；重复绑定抛 `ExtensionError`；扩展代码不能调 `_bind()`
- 绑定前访问受限：`config_value` 属性、`update_config()` 先 `_require_bound()`，
  未绑定抛 `ExtensionNotBoundError`；`get_config_schema()` 只读 `config_model`，unbound 也可用
- `id` 是 property：绑定后返回 `metadata.id`，未绑定返回 `_declared_id`；`__init__` 里
  **绝不能写 `self.id = ...`**（子类可能把 `id` 覆盖为只读 property → AttributeError），
  必须写 `self._declared_id`
- disabled / blocked 展示实例：`_register_display` 用 `Extension()` 建 unbound 实例，设
  metadata / state / failure_reason 后注册进 `extension_manager.registry`（不进
  `loader.extensions`，故 lifecycle 会跳过）；disabled 扩展不导入不绑定；依赖被阻塞的
  扩展标记 `blocked`

### 0.6 内置与用户扩展

- 内置扩展在 `Scripts/Extensions/Builtin/`（单文件）：`extension = Extension(id='List', name='在线玩家',
  version='1.0.0', types=('command',), builtin=True)` 构造 kwargs 传元数据，不继承
- 用户/市场扩展在顶层 `Extensions/`（目录式）：`Extension.toml` + `__init__.py` 入口模块
  （入口导出 `extension` 实例），如 `Html2Pic`（引擎）、`DefaultTheme`（主题）
- 清单文件名 **`Extension.toml`**（大写 E），`Loader.MANIFEST_FILE = 'Extension.toml'`；
  `_validate_compatibility` 对 `compatibility.unibot` 空或 `'*'` 直接通过，否则 `SpecifierSet` 校验
- Loader 跳过 `__pycache__` 与 `__init__.py`；`Config/Extensions.toml` 记录启停（缺失默认启用），
  `_read_enabled` 有实例缓存（`load()` 开头重置）

### 0.7 渲染架构

- 模板主题：Loader `_commit_renderers` 把 `RenderKind.theme` 扩展的 `Templates/` 目录注册为
  模板主题，key 优先取 `theme_name`，缺省用扩展 id；`Render.py._build_environment` 从
  `extension_manager.themes.get(config.image.theme)` 取目录，回退链「当前主题 → default →
  RuntimeError」。模板唯一来源为 `Extensions/DefaultTheme/Templates/`（`Resources/Images` 已删除）
- 引擎：`Manager.start()` 在 `config.image.mode` 开启时 `renderer_manager.setup('html2pic')`；
  图片模式关闭时 `_import_and_load` 跳过 render 类型扩展（disabled，reason「图片模式未开启」）
- Jinja2 环境 `enable_async=True`：模板渲染必须 `render_async()`；二次渲染
  `await environment.from_string(value).render_async(**vars)`（同步 `render()` 会产生未 await 协程警告）
- 配置注入：`_config_context`（async）预渲染含 `{{` 的字符串字段后再注入 `config`（深拷贝 +
  只读包装）；模板经 `config.xxx` 自读配置（如 `resolve_random(config.background)`），
  不依赖 render_image 注入的 background
- Jinja 全局函数：`random(dir)` 返回随机图片的**绝对路径**（模板自行包 `url()`，
  如 `url("{{ random('./Resources/Backgrounds') }}")`）；`resolve_random(value)` 处理
  静态配置字符串中的 `random("dir")` 文本语法并输出 `url("...")`；另有
  `resource_path` / `resource_url` / `resource_text` / `resource_bytes` 访问资源扩展
- 渲染调用统一 `render_template(name, size, **kwargs)`；尺寸 `(width, height)`，高度 0 自适应；
  上下文数据需 `encode_context()` 转义

### 0.8 存储

- `ExtensionConfigStore(root_dir, model)`：配置文件 `Config/Extensions/<id>.toml`；
  `extension.config.value` 返回校验后模型，`update(values)` 校验 + 原子写盘 + 更新缓存
- 行为：**无字段模型不创建配置文件**（并 `unlink(missing_ok=True)` 清理遗留空文件）；
  有字段模型文件缺失/为空时**自动创建默认配置**（`_atomic_write` 的 `mkdir(parents=True)` 保证目录）
- `ExtensionDataStore`：内置扩展指向 `Path('Data')` 根目录，用户扩展 `Data/<id>/`；
  `read_json` / `write_json` 读写 JSON（Utf-8）
- `_atomic_write(file_path, content: str | bytes)`：新增调用点需注意签名

### 0.9 依赖同步

- `Scripts/Extensions/Dependencies.py`：扫描顶层 `Extensions/` **已启用**扩展聚合去重
  `[dependencies].python`，合并写入 `pyproject.toml` `[project.optional-dependencies].extensions`
  组（**只增不删**，保留组内既有条目；组由框架独占维护，勿手动编辑）
- `Scripts/Api/Config/Driver.py`：安装适配器驱动时把底层包写入 `project.dependencies`

- 静态路径（`/market`、`/renderers`、`/themes`）在参数路由 `/{extension_id}` 前注册；

- 修改类接口 `Depends(require_role('admin'))`，列表/详情 `Depends(get_current_user)`
- 响应格式统一 `{'code': 0, 'data': ..., 'message': 'ok'}`

## 2. 命名规范

| 类型 | 规范 | 示例 |
|------|------|------|
| 文件名 | PascalCase | `Bot.py`、`Data.py`、`Server.py` |
| 类名 | PascalCase | `DataManager`、`ServerManager` |
| 函数/方法 | snake_case | `check_player()`、`get_permission()` |
| 变量 | snake_case | `uuid_caches`、`render_template` |
| 常量 | UPPER_SNAKE_CASE | `TOML_PATH`、`RESOURCES_DIR`、`MAX_HISTORY` |
| 配置字段 | snake_case | `command_enabled`、`sync_all_qq_message` |

**⚠️ 变量命名禁止使用缩写**，必须使用完整的、有语义的英文单词：

```python
# ✅ 正确
server_manager
player_name
message_content
response_data
command_enabled

# ❌ 错误
srv_mgr
plr_nm
msg_cnt
resp_d
cmd_en
```

- 变量名应清晰表达用途，宁可长一点也不要让人猜。
- 唯一例外：循环索引 `i`/`j`、异常对象 `e`/`error`、广泛认知的缩写如 `url`、`id`、`uuid`。

## 3. 导入规范

导入分三组，组间空一行，组内按字母排序：

```python
# 1. 标准库
import asyncio
import tomllib
from pathlib import Path

# 2. 第三方库
import nonebot
from nonebot.log import logger
from nonebot_plugin_alconna import Command, Match
from nonebot_plugin_alconna.uniseg import Image, UniMessage

# 3. 本地模块
from Scripts.Config import config
from Scripts.Globals import render_template
from Scripts.Managers import data_manager, server_manager
from Scripts.Utils import turn_message_text
from Scripts.Rules import command_group_rule
from Scripts.Extensions import command_manager, extension_manager
```

- 优先使用 `from X import Y`，避免 `import X` 后频繁 `X.Y`。
- 若有需导入相同目录下的模块，使用**相对导入**。
- **相对导入仅允许 `.`（同层）和 `..`（父级一层）**，禁止 `...` 及更深层相对导入。
- `Scripts/Extensions/` 包内同层模块互导用 `.module`（如 `from .Base import ...`）。
- 跨包或跨子目录引用一律用**绝对导入**，避免使用 `...` 或加深 `..` 层级。
  例如子目录 `Builtin/Commands/` 访问包根用 `from Scripts.Extensions import ...`，
  跨子目录用 `from Scripts.Extensions.Builtin.Services.PlayerService import ...`。
- 尽量少用 `..`：能用绝对导入表达的跨层引用优先用绝对导入（如
  `from Scripts.Extensions import ...`），仅在包内同层互导时使用 `.`。

## 4. 类型注解

- 使用 Python 3.10+ 联合类型语法：`str | None`，禁止 `Optional[str]`。
- 容器类型使用内置泛型：`dict[str, str]`、`list[str]`、`tuple[int, int]`。
- 只在类型不能由编辑器可靠推断、公共接口需要约束、Pydantic 模型字段或静态检查确有收益时添加类型注解。
- 局部变量、返回值显而易见的私有辅助函数、可由基类或赋值表达式推断的类型不重复标注。
- 不使用类型注解复述实现；复杂类型优先提取为有语义的类型别名。

```python
def get_player_name(name: str) -> str | None:
    ...

async def render_template(template_name: str, size: tuple[int, int], **kwargs) -> bytes:
    ...
```

## 5. 命令编写规范

**内置命令与用户扩展统一使用类式命令框架**：声明一个继承 `Command` 的命令类，
子命令用嵌套 `SubCommand` 类声明，由 `CommandManager.build()` 统一构建 matcher，
不要求作者拼接 Alconna DSL。

内置命令位于 `Scripts/Extensions/Builtin/`（一个文件一个命令，均以内置扩展
形式注册）；用户扩展在 `Extensions/` 下。

### 5.1 命令类声明

```python
from Scripts.Extensions import Command, SubCommand


class HelpCommand(Command):
    name = 'help'
    description = '查看所有可用命令的帮助信息。'
    usage = '.help [命令名称]'

    def declare(self):
        self.register_option('command', str, default=None, description='命令名称')

    async def handler(self, command: Match[str]) -> str | None:
        """文本分支：返回文本，由框架统一发送。"""
        return await turn_message_text(self.help_handler())

    async def image_handler(self, command: Match[str]) -> bytes | None:
        """图像分支：返回 PNG 字节，由框架在图像模式自动发送。"""
        commands = self.get_commands_list()
        return await render_template('Help', (600, 0), detail=None, commands=commands)
```

要点：

- **禁止在 `handler()` 内手动判断 `if config.image.mode:`**：需支持图片的命令覆写
  `image_handler`（返回 `bytes`），框架自动分发。
- **处理器通过 `return` 携带要发送的内容**（字符串 / 图片字节 / 片段列表 /
  异步迭代器），由框架统一 `matcher.finish()` 发送，处理器内无需接触 matcher。
- 返回 `None` 表示不发送（框架直接返回）。
- 需要逐行发送的内容使用异步生成器 + `turn_message_text()` 拼接为多行文本。也可以直接 yield 返回一行。
- 子命令使用嵌套 `SubCommand` 类声明，通过 `self.parent` 访问宿主命令实例。
- **定义顺序统一标准**：先完整定义主命令类，再依次定义子命令类（嵌套 `SubCommand`，
  每个子命令也先声明完整再定义其深层子命令）。子命令类不前置在父命令处理函数之前。
  类内方法顺序：**被 `@override` 覆写的方法（`declare()` / `handler()` /
  `image_handler()`，即框架要求实现/覆写的接口）统一放在最前面**，然后是类自身的
  私有处理函数，最后是嵌套子命令类。
- **处理函数归属统一标准**：每个命令的处理函数默认定义在**自己的类**内（如
  `remove` 子命令的解绑逻辑写在 `Remove` 类中）；仅当处理函数被**多个子命令公用**
  时才定义在父命令类下，并加分区注释（如 Bot 的 `_render_about` 被 `about` /
  `check` 共用）。子命令内不再通过 `self.parent.xxx` 调用父类的私有处理函数。
- 权限检查使用 `get_permission(session)`。
- 命令/子命令/参数名仅允许小写字母、数字、下划线。
- 可选参数（`required=False`）必须提供 `default`，否则校验失败；`register_option`
  等价于 `register_arg(..., required=False)`。
- 覆盖通过类继承实现：继承内置 `Command` 类，覆写字段/方法即可，未覆写的行为保留；
  覆盖命令按同名 `command_id` 注册取代内置定义（同一 `command_id` 重复注册会报错）。

### 5.2 扩展命令框架（Extension）

**内置命令与第三方扩展统一通过 `Command` / `SubCommand` 类注册声明式命令树**。

**惯例：扩展在文件开头实例化唯一 `extension` 实例，后续所有能力类都用
`@extension.register_xxx` 装饰器登记**（指令用 `@extension.register_command`、
服务用 `@extension.register_service`、渲染器用 `@extension.register_renderer`），
Loader 统一实例化并提交：

```python
from Scripts.Extensions import Command, Extension, SubCommand


# 唯一扩展实例放在开头
extension = Extension(config_model=None)


@extension.register_command
class WeatherCommand(Command):
    name = 'weather'
    description = '查询天气'
    usage = '.weather [城市]'
    
    @override
    def declare(self):
        self.register_option('city', str, default='SH')
        self.register_subcommand(Today())

    @override
    async def handler(self, city: Match[str]) -> str | None:
        return await turn_message_text(self.weather_handler(city.result))

    class Today(SubCommand):
        name = 'today'
        description = '今日天气'
        async def handler(self) -> str | None: ...
```

覆盖既有命令（继承内置命令类并覆写字段/方法，按同名 `command_id` 注册取代）：

```python
from Scripts.Extensions.Builtin.List import ListCommand
from . import extension
from typing import override

@extension.register_command
class MyListCommand(ListCommand):
    """只覆盖输出格式，数据获取逻辑继承不变"""
    description = '自定义列表（只显示在线）'
    usage = '.list'

    @override
    def list_handler(self, players): ...
```

**图像模式（image_handler）**：命令可覆写一个返回 `bytes` 的图像处理器，由框架在
`config.image.mode` 开启时自动分发并发送图片，无需在 `handler()` 内手动判断：

```python
class WeatherCommand(Command):
    name = 'weather'
    description = '查询天气'

    async def handler(self, session: Uninfo, city: Match[str]) -> str | None:
        return await turn_message_text(self.weather_handler(city.result))

    async def image_handler(self, session: Uninfo, city: Match[str]) -> bytes | None:
        return await render_template('Weather', (500, 0), city=city.result)
```

要点：

- `image_handler` 必须返回 `bytes`（图片字节）；框架收到后封装为
  `UniMessage(Image(raw=...))` 发送。
- 若图像处理器内无法生成图片（如权限不足、无数据），返回 `None`，
  框架检测到 `None` 即跳过图片发送，避免重复响应。
- `handler()` 只负责文本分支，不再包含 `if config.image.mode:` 判断；
  图像逻辑全部收敛到 `image_handler`，代码更清晰、职责单一。
- 子命令同样支持 `image_handler`（嵌套 `SubCommand` 内覆写）。

### 6.1 类与方法声明

- 类成员按「公开变量 → 私有变量 → 属性方法 → 私有方法 → 公开方法」的顺序定义；
  若按功能分组更清晰可以功能为准，但非必要不偏离该顺序。

- 优先使用实例方法；不访问实例状态时使用 `@staticmethod`，仅操作类级状态时使用 `@classmethod`。
- 覆写基类方法时使用 `@override`；只有确有抽象契约时才引入抽象方法。
- 参数较多时优先封装明确的数据模型，不用无语义的布尔参数堆叠调用。

## 9. 日志规范

使用 `nonebot.log.logger`，按语义选择级别：

| 级别 | 用途 | 示例 |
|------|------|------|
| `debug` | 模块加载、调试信息 | `logger.debug('加载命令 Bot 完毕！')` |
| `info` | 正常业务流程 | `logger.info(f'收到玩家 {player} 加入服务器通知！')` |

| `success` | 关键操作成功 | `logger.success('加载数据文件完毕！')` |

- 日志消息使用中文，直接说明动作、对象和结果，不重复模块名、调用链或无用上下文。
- 正常完成日志不强制使用感叹号；避免“开始处理”“处理完毕”等成对流水日志，除非排查耗时确有需要。
- f-string 内嵌变量，不使用 `%` 或 `.format()`。
- 异常日志只保留定位问题所需的信息；同一异常不在相邻层级重复记录。

## 10. 错误处理

- 网络请求、文件操作等可能失败的代码必须 `try/except`。
- 捕获后记录日志并返回有意义的用户提示，禁止静默吞掉异常。

```python
try:
    response = await client.get(url)
    if response.status_code == 200:
        return response.json()
    logger.warning(f'请求 {url} 失败：错误的状态代码 {response.status_code}')
except Exception as error:
    logger.warning(f'请求 {url} 失败：{error}')
```

- 面向用户的错误信息应友好、明确，告知原因和建议操作。

## 18. 避免 else

- **尽量不使用 `else` 分支**，优先通过提前返回（early return）、守卫子句（guard clause）、`match` 等方式表达逻辑。
- 保持逻辑简洁明了，不重复无用的判断；能从既有条件推导出的分支不重复书写。
- `if/else` 一律改写为提前返回：

```python
# ✅ 正确：提前返回
def check_permission(role: str) -> bool:
    if role == 'admin':
        return True
    return False

# ❌ 错误：else 分支
def check_permission(role: str) -> bool:
    if role == 'admin':
        return True
    else:
        return False
```

- `elif` 可用于互斥的多分支条件判断。
- 仅当去掉 `else` 会引入重复计算、额外状态、错误的控制流或降低可读性时保留，例如 `try/except/else` 的成功分支。

## 20. 调用与排版

- 函数调用在不超过项目行宽时写在一行，避免每个参数机械换行。
- 单行长度避免过短或过长，尽量保持在 70-120 字符之间（Ruff 行宽上限 120）；超过行宽由 Ruff 统一格式化，
  不要手工对齐参数或使用反斜杠续行。
- 简短的函数签名、容器和返回表达式同样优先单行；复杂表达式先拆成有语义的局部变量。
- 在保持可读性的前提下可适当压缩代码：善用海象表达式 `:=` 合并赋值与判断、
  三元表达式 `a if cond else b` 简化单行分支，不为压缩牺牲可读性。
- 项目使用 Ruff 检查和修复：提交前运行 `uv run ruff check --fix .`。
- 可运行 `ruff format` 统一格式化：docstring 规范即双引号，与格式化结果一致无冲突。
